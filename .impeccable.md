## Design Context

### Users

Pomogit is for solo software developers who want a focused bridge between intention and shipped work. They plan concrete outcomes, protect time to finish them, and close sessions with evidence such as a commit, pull request, or written result.

The product should reduce planning friction and make progress inspectable. It is not a generic Pomodoro timer, social network, or productivity-score dashboard.

### Brand Personality

Graphic, direct, assured.

Pomogit should feel like a carefully designed independent software product with the directness and graphic economy of Sprout: confident typography, plainspoken copy, useful humor in small details, and no ornamental polish that obscures the product.

The primary brand mark is the supplied woven geometric Pomogit symbol. Use it without redrawing or decorating it, preserve its square proportions, and adapt its monochrome color only for light/dark contrast.

### Aesthetic Direction

Use Sprout for graphic economy and Dither Kit as a restrained signature accent: near-white or near-black zinc canvases, near-black grotesk typography, solid electric-blue actions, thin neutral rules, compact navigation, generous whitespace, and ordered pixel texture only where it clarifies a working surface.

Replace the cream, forest, and acid-lime palette. Light mode uses white and blue-tinted zinc; dark mode follows Dither Kit's near-black zinc field. Electric blue is reserved for intent, selected states, and current work. Drop glassmorphism, decorative ASCII, atmospheric gradients, soft auras, giant framed cards, random glyphs, conventional dashboard tiles, and generic blue-purple glow effects.

Layouts should be flat, crisp, and grid-aware. Use small radii, one-pixel outlines, firm rectangular controls, and almost no shadows. Motion should be quick and functional, using opacity and transform only.

The product shell must always answer three questions without interpretation: where am I, what is moving, and where can I go next. The rebrand has one primary Work screen rather than separate Home and Board surfaces. Work owns current context, ordered Ready tasks, Inbox capture, completed tasks, and inline checkpoint history. Focus and Checkpoint will be temporary overlays in later phases. Settings remains the only utility destination. Canvas, standalone Worklog, charts, and shortcut rows are out of scope.

Keep marketing composition on the landing page. Inside the workspace, use fixed-size application typography, compact page titles, section rules, and task-dense layouts. A product route should feel like a specific working surface, never like another homepage with a giant slogan.

On desktop, the sidebar sits directly on the application background outside the rounded workspace frame. Only the page region is wrapped: its independently scrolling body occupies one outlined, rounded surface. Keep the navigation rail visually quiet and borderless so it reads as the shell around the workspace, not as a second card. Do not add redundant locality labels to the rail. Navigation uses transparent rows with a quiet hover wash and one small active indicator; it must not resemble a stack of buttons. Primary actions are solid electric blue, secondary actions use a quiet neutral fill, and ghost actions remain transparent. Controls use tight radii with no gradient underlay, texture, inset shadow, or pressed bevel. Inputs and textareas are plain, outlined working surfaces. Hover feedback never moves controls or changes surrounding geometry.

Dither Kit supplies controlled digital grain to Work's current-task surface and primary action buttons. Primary Dither buttons sit on a solid blue base, have no painted border, and keep their label above the texture. Never use dither on navigation, fields, filters, secondary actions, or selected states. Charts and invented productivity metrics are forbidden.

### Design Principles

1. Make Pomogit recognizable through graphic economy, not decoration.
2. Let the work outcome lead; the timer supports it.
3. Show the real product as the visual centerpiece.
4. Use white space, black type, thin rules, and rare lime accents to create hierarchy.
5. Close every completed session with inspectable evidence.
6. Preserve accessibility, reduced motion, keyboard use, and responsive composition.
7. Never rely on icon-only navigation or color alone to communicate location and progress.
8. Separate global journey switching from page and section navigation.
9. Prefer quiet utility surfaces over diagrammatic navigation or oversized containers.
10. Keep the sidebar outside one rounded page wrapper, with the persistent header inside that wrapper.

## Implementation Brief

### Feature Summary

Rebuild Pomogit around three PostgreSQL-backed records: Task, FocusSession, and Checkpoint. Phase 2 exposes one Work screen with a priority-driven Now surface, a short Ready list, collapsed Inbox capture, and collapsed Done rows whose checkpoint histories expand inline. Later phases add Focus and Checkpoint overlays, then the first-visit Landing and final Settings experience.

### Primary User Action

Choose an outcome, focus on it, and leave evidence that the work moved forward.

### Visual Direction

Translate Sprout's graphic economy into an original Pomogit product: near-white ground, near-black grotesk type, electric-blue actions, thin gray rules, compact mono metadata, small-radius rectangles, and restrained Dither texture. Use licensed open-source typography. Do not copy another product's logo, illustrations, source code, or proprietary assets.

### Layout Strategy

Work is a single vertical decision surface: Now first, no more than four additional Ready tasks, then collapsed Inbox and Done sections. The current task receives the only textured surface and primary action. Lists remain flat and divided by rules rather than becoming card grids. A Done row expands its own checkpoint chronology so the user never leaves Work to recover history.

### Key States

- Empty workspace with first-task capture inside Now.
- Active and paused sessions surfaced above all task inventory.
- Most recent continued checkpoint with its saved next step.
- First explicitly ordered Ready task when no session or continuation exists.
- Short and expanded Ready lists.
- Collapsed and expanded Inbox with task capture and Ready promotion.
- Collapsed Done inventory with each task's checkpoint history expanded inline.
- API loading, failure, retry, light, dark, keyboard, mobile, and reduced-motion states.

### Interaction Model

Work derives its Now state from the PostgreSQL API in strict priority order: open session, newest continued checkpoint, first ordered Ready task, then task capture. New tasks enter Inbox except the first task in an empty workspace, which enters Ready. Inbox tasks can be promoted to the end of Ready; Ready tasks can return to Inbox. Done rows fetch and reveal their checkpoint history in place. Phase 2 does not start, pause, end, or checkpoint a focus session; those controls are wired in later phases.

### Content Requirements

Prefer short working language: “Work,” “Inbox,” “Ready,” “Start focus,” “Resume,” “Add checkpoint,” “Continue task,” and “Done.” Examples should resemble real software work. Avoid productivity claims, streak language, vague inspiration, and redundant explanatory copy.

### Recommended References

- Spatial design for editorial composition and app-shell adaptation.
- Typography for marketing-to-product hierarchy.
- Color and contrast for dual green-forward themes.
- Interaction design for the queue, timer, and evidence forms.
- Motion design for entrances and focus-state feedback.
- Responsive design for landing and application modes.
- UX writing for short labels, errors, and empty states.

### Deferred

- Focus and Checkpoint overlays until Phases 3 and 4.
- Final first-visit Landing and Settings export until Phase 5.
- GitHub integration, Canvas, standalone Worklog, analytics, shortcut customization, import, notifications, recurring work, and multi-workspace collaboration.
